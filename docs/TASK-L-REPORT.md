## 1. المشاكل التي اكتُشفت

1. لوحة Telegram الرئيسية كانت لا تزال تعرض أزرار الأسواق القديمة وستة عناصر مختلفة عن المطلوب.
2. عبارة حالة البيانات في كرت الإشارة كانت تقارن درجة جودة البيانات (0–12) بالرقم 6، وكانت النتيجة تظهر `LIMITED` غالباً أو `LIVE` عند جودة متوسطة فقط.
3. الباك-تست كان يدخل بسعر إغلاق شمعة القرار ويُسوّي الصفقة عند أول شمعة تفتح بعد الانتهاء، أي بتأخير شمعة كاملة وتسريب حركة السعر بعد وقت الانتهاء.
4. سجل الباك-تست لم يكن يحفظ سبب النتيجة ولا الاستراتيجيات ولا وقت التسوية الفعلي ولا مدة الصفقة.
5. جسر ExpertOption كان يعيد استخدام اشتراكات الشموع دون حد أعلى، وقد ظهر فعلياً `EO: ERROR_TOO_MANY_ASSETS` أثناء جلب Luxury وCricket.
6. لم يكن هناك مسار عام موثّق لجلب تاريخ الشموع الحقيقي بغرض التحقق المستقل، لذلك كانت الاختبارات تعتمد على مسار محلي أو على أدوات داخلية فقط.

## 2. السبب الحقيقي لكل مشكلة

- **اللوحة:** بقايا Task H داخل `bot/keyboards/menus.py` و`bot/formatting.py`.
- **حالة البيانات:** خلط بين `max = 12` وحد سابق 65 في `bot/formatting.py`.
- **الباك-تست:** استخدام `entry.close` و`candles[settle_index].close` مع البحث عن أول شمعة `time >= expiry` بدل آخر شمعة تُغلق قبل الانتهاء.
